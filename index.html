Что делает OmniMigrate

Автономный конвейер, который доводит миграцию до работающего кода, а не останавливается на подсказках.

AST-анализ

LibCST детерминированно находит deprecated импорты, Python 2 конструкции, секреты и N+1 — до обращения к LLM.

Self-healing loop

Неудачный результат автоматически уходит на починку с текстом ошибки песочницы — без человека в контуре.

Песочница

Сгенерированный код проверяется компиляцией и запуском до того, как попадёт к вам. Регрессии ловятся на этапе миграции.

Urgent / normal / bulk — срочные миграции выполняются раньше. Горизонтальное масштабирование воркеров.

Git-пайплайн

Repo → token → branch, живой прогресс и просмотр diff до пуша. Автономный режим для целых репозиториев.

На конкретных примерах

Что именно меняет движок

Три типичных случая: от удалённого API до небезопасной практики. Слева — что вы присылаете, справа — что получаете на выходе после проверки в песочнице.

Python 2 → Python 3.12
automated
До
from urlparse import urlparse
import urllib2
def load(url):
    resp = urllib2.urlopen(url)
    return resp.read()
После
from urllib.parse import urlparse
import urllib.request
def load(url):
    with urllib.request.urlopen(url) as resp:
        return resp.read()

Почему это важно: urlparse и urllib2 удалены из Python 3 — код просто не запустился бы без этой миграции.

Устаревший datetime.utcnow
deprecation
До
from datetime import datetime
created = datetime.utcnow()
После
from datetime import datetime, timezone
created = datetime.now(timezone.utc)

Почему это важно: datetime.utcnow объявлен устаревшим — новый вариант корректно хранит временную зону, что критично для аудита и времени событий.

Хардкод-секрет в коде
security N+1
До
DB = "postgres://admin:hunter2@db/mig"
После
DB = os.environ["DATABASE_URL"]

Почему это важно: AST-анализ обнаруживает захардкоженные секреты и пароли и выносит их в переменные окружения — они перестают светиться в репозитории и коммитах.

Как это работает

Пять шагов до современного кода

1

Парсинг

LibCST обходит AST и собирает карту находок: deprecated импорты, устаревшие конструкции, проблемы безопасности, паттерны N+1.

2

Анализ

Находки превращаются в строгий промпт для движка — инженер-LLM получает полный контекст изменений.

3

Рефакторинг

Модель возвращает только код: без пояснений, с сохранением сигнатур функций и внешнего контракта.

4

Верификация

Песочница компилирует и запускает результат в изолированном процессе. Ошибка — повод для починки, а не для выдачи.

5

Готово

Формируется unified diff и метрики; статус стримится через Redis в живой UI. Миграция завершена и проверена.
